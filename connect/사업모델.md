# 윈-윈 커넥트 사업 모델 정리

> 작성 2026-11-05, 수정 2026-11-05 (서비스명·수수료 확정 반영). 금액은 `js/config.js`에서 바로 바꿀 수 있습니다.

## 한 줄 정의
**"만들 곳을 못 찾는 사업자"와 "일감이 부족한 공장"을, 대표의 인맥으로 직접 연결해 주고 수수료를 받는 중개 서비스.**

## 1. 누가 돈을 내고, 왜 내는가

| | 수요자 | 공급자 |
|---|---|---|
| 누구 | 소규모 브랜드·셀러, 제작을 알아볼 인력이 없는 작은 사업장 | 생산 여력은 있는데 영업력이 없는 공장·인쇄소·가공업체 |
| 문제 | 수량이 적어 공장이 안 받아줌 / 어디에 물어볼지 모름 / 비교할 시간이 없음 | 거래처가 정해져 있어 가동률이 낮음 / 영업 인력 없음 |
| 우리가 주는 것 | 질문별 체크리스트로 정리한 **공급자 리스트** (연락처 포함) | **검증된 수요자**의 구체적인 의뢰 |
| 내는 돈 | **연결비 50,000원 (정액)**: 리스트의 연락처를 받을 때 | **성사 수수료 100,000원 (조건부)**: 계약됐을 때만 |

수요자는 "시간을 아낀 값", 공급자는 "영업을 대신한 값"을 냅니다. 양쪽 모두 결과가 있을 때만 냅니다.

## 2. 진행 흐름 (운영자 기준)

```
① 요청서 접수 (홈페이지): 품목·수량·예산·납기 + 공급자에게 확인할 질문
   └ 의뢰번호 자동 발급 (예: R261105-001), 상태: 신규
② 하루 안에 전화 → 요구사항·질문 확인 (빠진 질문은 관리자 화면에서 추가)
   └ 상태: 확인중
③ 인맥·등록 공급사 2~3곳에 "윈-윈 커넥트 소개 건, 의뢰번호 ○○"로 연락 → 질문마다 ● 가능 / ▲ 조건부 / ✕ 불가 체크
   └ 상태: 업체수배 (관리자 화면 "공급자 리스트 작성"에서 입력, 임시 저장 가능)
④ "저장하고 링크 만들기" → 수요자에게 전용 링크 전송 (메시지 문구 자동 생성, 복사 버튼)
   └ 상태: 리스트전달. 이 시점이 소개일로 기록됨. 이때는 "공급사 A, B"로만 보임
⑤ 연결비 50,000원 입금 확인 → "연락처 공개" 체크 후 저장 → 같은 링크에서 업체명·연락처 공개
⑥ 수요자가 의뢰번호를 말하며 업체에 직접 연락
   └ 상태: 연결완료
⑦ 계약 확인 → 공급자에게 성사 수수료 100,000원 청구
   └ 상태: 정산완료
```

**수요자가 받는 화면** (`report.html?demo=1`, 연락처 공개 상태는 `report.html?demo=1&reveal=1`에서 미리 볼 수 있음)
- 업체별 적합도(%) 순으로 정렬. 가능 1점, 조건부 0.5점으로 확인한 질문 기준 계산
- 질문별 체크 결과와 메모, 단가·MOQ·납기, 상담 메모
- 업체가 2곳 이상이면 질문 × 업체 비교표

## 3. 수수료를 지키는 장치
중개업은 "소개받고 몰래 직거래"가 가장 큰 위험입니다.
- **공급사 등록 시 동의**: "소개받은 고객과 1년 안에 계약하면 성사 수수료 대상" (등록 양식에 별도 체크로 반영, 동의 일시가 시트에 저장됨)
- **연락처는 연결비 확인 후 공개** → 리스트만 보고 빠지는 경우에도 업체명이 노출되지 않음
- **소개 기록 자동 저장**: 리스트 제공일(=소개일), 열람 기록, 의뢰번호 → `법령_계약_점검.md` 2-4 참고
- 반복 거래가 많은 공급자는 **월 정액 제휴**(예: 월 10~30만 원, 소개 무제한)로 전환 제안
- 생산 후 **보관·출고는 KB물류로** 이어 받으면 수수료 외 지속 매출 (가장 큰 강점)
- 계약서는 일반 용역 계약 형태로 진행 → 초안과 법령 점검은 `법령_계약_점검.md` 참고

## 4. 초기 공급자 풀 만들기 (지금 바로 할 일)
1. 기존 거래처 중 제조·인쇄·포장이 가능한 곳 10곳 목록화 → 공급사 등록 링크 보내기
2. 그 거래처들이 쓰는 공장·인쇄소를 소개받기 (인맥의 인맥)
3. 3PL 화주(셀러)들에게 "제작처 연결도 해 드립니다" 안내 → 첫 수요자 확보
4. 첫 5건은 연결비 할인으로 사례를 만들고, 동의받아 '지금 찾고 있는 일' 게시판에 실제 사례로 교체
   (지금 게시판 4건은 **예시**라고 표시돼 있습니다 — 실제 의뢰로 바꾸면 `example: true`를 지우세요)

## 5. 숫자로 보기 (가정)
| 항목 | 가정 |
|---|---|
| 월 의뢰 | 10건 |
| 명함 전달까지 가는 비율 | 70% → 7건 × 5만 원 = **35만 원** |
| 실제 계약 비율 | 40% → 약 3건 × 10만 원 = **30만 원** |
| 월 합계 | **약 65만 원** + KB물류 보관·출고 연계 매출 |

수수료가 정액이라 거래 금액이 큰 건도 10만 원으로 같습니다. 대신 계산이 단순하고 공급자가 부담 없이 참여할 수 있습니다. 큰 거래가 많아지면 "거래액 일정 비율" 조건을 추가하는 것을 다시 검토하세요. 의뢰 수가 늘면 비용 구조는 거의 그대로라 이익이 커집니다. 다만 건당 업체 수배에 드는 시간(전화 2~4시간)이 실제 병목이므로, 공급사 DB를 분야별로 쌓을수록 빨라집니다.

## 6. 앱 로드맵
| 단계 | 내용 | 비용·기간 |
|---|---|---|
| **1단계 (완료)** | 홈페이지 + 설치형 웹앱(PWA) + 구글 시트 접수 + 관리자 페이지 | 무료, 바로 |
| **2단계** | 플레이스토어 등록: PWABuilder(pwabuilder.com)에 사이트 주소 입력 → 안드로이드 패키지 생성 → 구글 개발자 계정(25달러 1회)으로 등록 | 1~3일 |
| **3단계** | 앱스토어 + 푸시 알림: Capacitor로 감싸서 iOS/Android 빌드. 새 의뢰 알림, 진행상태 알림 | 애플 개발자 연 129,000원 / 1~2주 |
| **4단계** | 회원 기능: 수요자는 내 의뢰 진행상황 보기, 공급자는 맞는 의뢰 알림 받고 "가능" 응답. 이때 구글 시트 → Supabase/Firebase 같은 DB로 이전 | 의뢰가 월 30건 넘을 때 |

앱스토어는 "웹사이트를 감싸기만 한 앱"을 거절하는 경우가 있어, 3단계에서 푸시 알림·진행상황 조회 같은 앱 기능을 함께 넣는 것을 권장합니다. 플레이스토어(2단계)는 PWA 그대로 등록이 잘 됩니다.
