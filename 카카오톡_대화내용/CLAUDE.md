# 카카오톡 대화 관리 (KB물류)

사용자는 **KB물류(3PL, 경기 파주) 대표 권봉구**. 카톡에서 `[KBlogistics]` 발신자가 사용자 본인.
목적: ① 거래처 요청이 빠짐없이 처리됐는지 점검 ② 반복 질문에 카톡 검색 없이 답하기.

## 폴더 구조
- `00_원본/신규/` — 새로 내보낸 `KakaoTalk_*.txt`를 여기에 넣기 (루트에 넣어도 됨)
- `00_원본/처리완료/` — 병합 끝난 원본 보관
- `01_대화방/<방이름>.txt` — 대화방별 누적 마스터 (직접 수정 금지, 스크립트로만 갱신)
- `02_요청사항_점검.md` — 미처리/확인필요/대기/예정 목록 (상단에 점검 범위 날짜 기록)
- `03_지식베이스.md` — 바로 답변용 정보 (단가, 입수량, 유통기한, 주소, 절차)
- `tools/병합.ps1`, `tools/추출.ps1`

## 업데이트 절차 (새 내보내기 파일이 들어오면)
1. `powershell -ExecutionPolicy Bypass -File tools\병합.ps1` — 방 이름(파일 첫 줄) 기준으로 마스터에 병합. 마스터의 마지막 날짜부터는 새 파일 내용으로 교체되므로 중복 없음.
2. `02_요청사항_점검.md`의 점검 범위 끝 날짜부터 추출:
   `powershell -ExecutionPolicy Bypass -File tools\추출.ps1 -Since <YYYY-MM-DD> -Out <스크래치패드>\recent.txt`
   (점검 끝 날짜 당일도 포함해서 다시 볼 것 — 그날 오후 대화가 추가됐을 수 있음)
3. 추출본을 읽고:
   - 기존 미처리/확인필요 항목 중 완료 근거(송장 공유, "완료/입고되었습니다", 입금 확인 등)가 나오면 ✅로 옮기거나 삭제
   - 새 요청 중 KBlogistics의 결과 보고가 없는 건 추가
   - "넵 알겠습니다"만 있고 결과 보고 없는 건 = 미처리/확인필요
4. 재사용 가능한 사실(단가, 입수량, 유통기한, 주소·연락처, 절차, 거래처 규칙)은 `03_지식베이스.md`에 출처(방이름 날짜)와 함께 추가·갱신. 값이 바뀌면 최신으로 교체하고 기준일 갱신.
5. 점검 범위 날짜 갱신.

## 질문에 답할 때
- 먼저 `03_지식베이스.md` → 없으면 `01_대화방/` Grep 검색 → 찾은 답은 지식베이스에 추가.
- 유통기한·재고처럼 변하는 값은 기준일을 함께 말할 것.

## 주의
- 비밀번호·인증번호·계좌번호 등은 지식베이스에 저장하지 않음.
- 하늘같은남수경님·한정오 방에는 개인 대화가 섞여 있음 — 업무 관련만 추출.
- 개별 소비자(택배 수령인) 개인정보는 지식베이스에 넣지 않음 (요청사항 추적에 필요한 이름·송장만).
- PowerShell 5.1이라 `.ps1`은 UTF-8 **BOM**으로 저장해야 한글이 깨지지 않음. Python 미설치.
